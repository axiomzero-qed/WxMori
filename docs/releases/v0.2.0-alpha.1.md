# v0.2.0-alpha.1 Release Candidate / 候选版

**Status / 状态:** Release CI is pending; this note records the candidate and observed local evidence, not a completed publication. / 发布 CI 尚待完成；本文记录候选版本与已观察的本机证据，不代表已完成发布。

## Changes / 变更

**中文：**

- Windows AMD64 登录时实验性捕获。默认 `auto` 动态识别 AES 密钥设置函数并用硬件执行断点；会短暂暂停微信线程、设置后恢复调试寄存器，不修改代码或注入 DLL。`read_only` 仅轮询可读内存。MCP `capture_key` 和 CLI `key capture` 均支持模式选择；须等待 `ready_for_login=true` 后再请用户登录。
- 仅保留 HMAC 验证通过的每库密钥，存入配置文件旁 `.wxmori-keys/` 的 DPAPI `CurrentUser` 密钥环；可自动供后续解密使用。手动 `key_file`/`WXMORI_MASTER_KEY` 保留为兼容回退。
- 加密 WAL 在私有副本校验并回放；源数据库不修改。非空加密 WAL 在已发布 `v0.1.0-alpha.1` 中仍不支持。

**English:**

- Experimental login-time capture on Windows AMD64. Default `auto` dynamically recognizes the AES key-setup function and uses hardware execution breakpoints; it briefly pauses WeChat threads and restores debug registers, without code patching or DLL injection. `read_only` polls readable memory only. MCP `capture_key` and CLI `key capture` accept a mode; wait for `ready_for_login=true` before asking the user to log in.
- Only HMAC-verified per-database keys are retained in a DPAPI `CurrentUser` keyring under `.wxmori-keys/` beside the config; later decrypt operations can load it automatically. Manual `key_file`/`WXMORI_MASTER_KEY` remains as a compatibility fallback.
- Encrypted WAL is validated and replayed in private copies without modifying source databases. Published `v0.1.0-alpha.1` still does not support non-empty encrypted WAL.

## Validation / 验证

**中文：** 本机 `go test ./...` 与 `go vet ./...` 通过。Luna 通过 Python stdio MCP 宿主，对一个 Weixin 4.1.15.56 单账号完成登录捕获：12/12 核心数据库密钥通过 HMAC，微信退出后新进程在无手动主密钥时从 DPAPI 重载，状态 ready，用户指定会话精确查询返回一个结果。TXT 和 JSONL 各 381 条、导出摘要匹配且 UTF-8 有效；TXT 的 381 个标题及 235 条多行正文均完整，JSONL 有 381 行。该样本 12 个 WAL 文件各有旧代次尾帧被排除，当前代次提交帧为 0；因此成功导出并不证明真实提交帧回放，提交帧回放目前由合成测试覆盖。真实快照源文件大小/修改时间指纹稳定；源哈希未在该实测中验证。自动捕获验证仅限此 Windows/Weixin 版本、单账号与 Luna/Python stdio 宿主；其他版本、模型及宿主未验证。当前发布 CI 待完成。

**English:** Local `go test ./...` and `go vet ./...` pass. Through a Luna Python stdio MCP host, a login capture on one Weixin 4.1.15.56 account HMAC-verified keys for 12/12 core databases. After WeChat exited, a fresh process reloaded them from DPAPI without a manual master key; status was ready, and exact lookup of the user-specified session returned one result. TXT and JSONL each contained 381 records, matching export hashes, and valid UTF-8; TXT preserved all 381 headers and 235 multiline bodies, and JSONL had 381 rows. Each of the 12 WAL files had an excluded stale-generation tail, and there were zero current-generation committed frames; successful exports therefore do not validate real committed-frame replay, which currently has synthetic test coverage only. Real-snapshot source size/mtime fingerprints remained stable; unchanged source hashes were verified only by synthetic snapshot tests. Automatic capture is validated only for this Windows/Weixin version, account, and Luna/Python stdio host; other versions, models, and hosts are untested. Release CI is pending.
